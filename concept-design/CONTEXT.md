# JARVIS — Compressed Context (v0.1 · 2026-11-17)

> 본 개발 착수 시 **이 파일을 먼저 읽을 것**. 최초 요구사항 대화 + 레퍼런스 스크린샷 4장을 압축한 요약본.
> 레포가 **public** 이라 원본 스크린샷(동료 이름·고객사 프로젝트명 포함)은 커밋하지 않았고, 아래에 **익명화된 구조 정보만** 남김.

---

## 1. 한 줄 정의
글로벌 조직관리용 **timesheet + 업무진행세부계획** 작성을 돕는 사내 그룹웨어 헬퍼 웹앱 "JARVIS".
개인이 30분 단위로 기록한 업무 로그(Google Sheets/Excel)를 → **그룹 지정 프로젝트명**으로 매핑 → 담당자별 **그룹 timesheet 포맷** + **주간 업무진행세부계획** 으로 자동 변환.

## 2. 해결하려는 문제 (Pain point)
- 그룹(본사)이 **새 프로젝트명을 수시로 신설** → 한국 담당자가 놓치면 해당 시간이 엉뚱한 행/일반업무로 기록됨.
- 한국 현지에서는 그룹 프로젝트명이 아니라 **로컬 호칭**(한글 약칭)으로 부름 → 수작업 매핑 필요.
- 담당자마다 개인 기록 시트 **작성 스타일이 제각각**.

## 3. 용어
| 용어 | 의미 | 예 (가상) |
|---|---|---|
| Group Project (그룹 프로젝트명) | 그룹이 지정한 공식명. SharePoint 엑셀 행 이름 | `2071--<Customer> Marine Flood Light`, `<Product> Bar Redesign` |
| Local alias (로컬 호칭) | 한국 팀이 부르는 이름. 1:N 가능 | `플루드램프`, `<제품>_2nd_리디자인` |
| Timelog category | 프로젝트 외 업무 공식 분류 (`00.Timelog--…`) | 아래 §4-A 목록 |
| 30-min log | 개인 일일 기록 (30분 = 1 slot, 0.5h) | Google Sheet, 하루 1탭 |
| Weekly plan (업무진행세부계획) | 주차별 업무 블록 목록 | §4-B |
| Group timesheet | 그룹 제출용 매트릭스 | §4-A |

## 4. 소스 포맷 명세 (스크린샷 분석, 익명화)

### 4-A. Group timesheet (SharePoint xlsx · 이미지 1)
- **하루 = 1블록**. 상단 병합셀에 날짜(`2026-11-02`). 열 = **엔지니어(약 11명, 이니셜/영문 이름)** + 맨 오른쪽 `D-sum`(프로젝트별 합). 엔지니어 헤더는 녹색 배경 + 45° 회전 텍스트.
- 행 = `No.` | `Project`
  - **1–21: 그룹 프로젝트** (흰/회색 교차). 이름 패턴 혼재:
    `NNNN--<Customer> <Product> [- Variant]`, `NNNNA--…`(파생 코드), `NNNN - <Product>`, 코드 없는 이름(`<Product> Redesign`, `<System> Implementation`).
  - **22–28: Timelog 카테고리** (노랑 `#FFFF00` / 주황 `#FFC000` 교차, Leave 행은 녹색). 영문+한글 병기 — 고정 목록:
    1. `00.Timelog--Change Requests (non-project) 변경 요청 대응 (프로젝트 외 업무)`
    2. `00.Timelog--Innovation / Pre-Project work (No project listed) 신규 기술 개발 및 프로젝트 착수 전 업무`
    3. `00.Timelog--Leave(휴가 및 휴무)`
    4. `00.Timelog--Quality issue resolution & testing (Existing products) 기존 제품 품질 문제 해결 및 시험`
    5. `00.Timelog--Quotation Support (non-project) 견적 검토 및 지원 (프로젝트 외 업무)`
    6. `00.Timelog--Third Party Product Benchmarking 타사 제품 벤치마킹 및 분석`
    7. `00.Timelog--Training & Self Development 교육 및 자기계발`
  - (번호 없음) **엔지니어별 프로젝트 소계 행** — 일부 셀 분홍 하이라이트(조건부 서식 추정).
  - **로컬 섹션(녹색 계열)**: `일반업무(Mail발송, 미팅조율, 리소스정리, 개발 등)`, `회의(개발, 품질, Gemba walk, etc..)`, `Support (생산, SCM 등)`, `<계열사/협력사> 금형 Support`, `Company Leave(회사지정휴가)`, `P&C(TownHall, plogging, 소방교육및훈련,청소)` — 합계 열 빨간 글씨.
  - `Indivisual Sum`(원문 오타 그대로) = 엔지니어별 하루 합 (보통 **8.00**, 초과 시 9.00 등). 마지막 `Biz Trip` 행.
- 값: 시간(h), **0.5 단위**, 소수 2자리 표기. 빈칸 = 0.
- ⇒ "담당자의 timesheet 포맷" = 이 매트릭스에서 **해당 엔지니어 열**(일자별). 앱은 ①팀 시트의 내 열 채우기, ②개인용 요일×프로젝트 시트 두 방식을 지원해야 함.

### 4-B. Weekly plan / 업무진행세부계획 (Excel 표 · 이미지 2)
- 열: `Week` | `Project`(**로컬 호칭**) | `Work` | `Item` | `Engineer` | `시간` | `접수일자` | `Due date` | `예상시간` (전 열 AutoFilter).
- 규칙(관찰):
  - Week = ISO 주차 (2026-11-02~06 → 45).
  - 1행 = **연속된 동일 업무 블록 1개** (30분 slot 병합). 같은 날 같은 업무도 중간에 끊기면 별도 행.
  - Project: 일반/회의는 `일반업무`, 프로젝트는 로컬 호칭 (`<제품>_2nd_리디자인`, `<고객>_<모델>_<영문>`).
  - Work: 회의 → `회의`, 그 외 → `기타`.
  - Item: `<접두어> | <설명>`. 회의 → `INT | Daily_Scrum`, 업무 → `개발 | 이메일 및 일반업무`, `개발 | <프로젝트 설명>`.
  - 접수일자 = Due date = 기록일, 예상시간 = 시간 (현재는 실적=계획 동일 입력).

### 4-C. 개인 30-min log (Google Sheets · 이미지 3)
- 1탭 = 1일 (탭명 예: `Dec16`). 상단: `날짜 | 2026 | Dec | 16`.
- 행 48개: `00:00`~`23:30`. 열:
  `시간` | `구분`(드롭다운, 색 칩) | `분`(30) | `내용` | `몰입도 0~3` | `평가 1~5` | `소요시간(0.5=30분)` | `일일평가`
  - 구분 헤더 힌트: `(수면, 휴식, 정비, 식사, 간식, 업무, 강의, 운전, 독서, 공부, 운동, 여가, 폰, 기타)`
  - 실제 사용값: `출근전`, `일반`, `회의`, `<프로젝트 로컬 약칭>`(예: 2~4자 한글), `점심`, `휴가`, `퇴근`(=퇴근후).
  - 내용 예: `출근 07:28`, `이메일 및 일반업무`, `INT | Daily_Scrum`, `개발 | <프로젝트>`, `INT | Weekly 품질회의`, `퇴근 16:30`.
- 우측 요약 패널:
  - **결과보고**: 항목별 할애시간 (`출근전`, `퇴근후`, `점심`, `휴가`, `일반`, `회의`, 프로젝트 로컬 약칭 ×8, …) — `N시간 M분` 표기.
  - **종합의견**: 휴식(수면·휴식·정비·식사·간식) / 업무(업무·강의·운전) / 자기계발(독서·공부·운동) / 기타(여가·셀폰·기타) / **업무 합계**(예: 8시간 30분).
  - 평가(질) 1~5 분포, 몰입도 0~3 분포, `Perfect Day Score`, 카테고리 파이차트, 그래프 데이터(항목·%·분).
- ⇒ **업무 카테고리 slot만** 추출 → 로컬 약칭 → 그룹 프로젝트 매핑 → §4-A, §4-B 생성.

### 4-D. UI 스타일 레퍼런스 (이미지 4, 외부 디자인 샷)
Bento grid 대시보드. 좌측 세로 내비 레일, 웜 크림/세이지 배경, 딥그린 카드 + 오렌지 포인트, 24px 라운드, 큰 숫자 타이포, 필(pill) 탭. → `README.md §2` 디자인 토큰으로 반영. (저작권 이슈로 이미지 미보관)

## 5. 사용자 요구사항 (원문 요약)
1. **웹**에서 동작, **React**. 프론트엔드 + **DB** 관리.
2. **계정별 접근권한**. **관리자**가 사용자 **초대**, 사용자는 **이메일 계정으로 로그인**.
3. 입력 UI는 **Excel 형식**(스프레드시트 그리드). **xlsx 입출력** — Google Sheets에서 내보낸 파일/그대로 사용 가능해야 함.
4. 문서를 분석 → **담당자 지정** → 해당 담당자의 **timesheet 포맷** + **시간별 세부 업무 기록**(업무진행세부계획) 생성.
5. 담당자별 작성 스타일이 다르므로 **스타일을 제안하는 템플릿 엑셀**을 출력.
6. **휴가**를 캘린더에서 바로 작성.
7. 내비: **Home**(대시보드 형태, **내용은 아직 정의하지 말 것**), **Timesheets**, **환경설정**. (+ 관리자 메뉴)
8. 신규 그룹 프로젝트 **누락 방지**가 핵심.
9. SharePoint 직접 접근은 어려울 것 → 사람이 수시로 추가. **연동 방법 있으면 가이드**.
10. **AI가 필요하면 API 키로 연동** (토큰 비용 감수).
11. UI 컨셉은 **Higgsfield**로(Claude 이미지 생성 X), **저해상도**. 결과는 레포 `concept-design/`에 기록 + 리소스는 압축 컨텍스트로 보관.

## 6. 컨셉 단계에서 내린 결정 / 가정
- 앱 이름 `JARVIS`, 부제 `Internal Groupware Assistant`. UI 언어는 영어 라벨 기본(+한글 데이터). 다국어(i18n ko/en)는 본 개발에서.
- Timesheets 하위 탭 5개: **Daily Log · Weekly Plan · Group Timesheet · Projects · Leave**. (휴가는 Timesheets 하위 — Leave 행 자동 반영 때문)
- Admin 메뉴는 관리자에게만 노출(내비 하단). Settings는 개인 + 연동 + AI + 템플릿.
- 신규 프로젝트 감지 = **마스터 시트 import 간 diff** + "alias 없음/기록 0h" 상태 → 오렌지 알림 카드.
- Export 전 **Validation**: 일 합계 = 근무시간(기본 8.0h), 미매핑 시간 0h.
- AI는 **필수 아님**. 결정론적 로직(파싱·집계·diff)이 기본, AI는 매핑 제안·비정형 시트 해석 보조(옵트인).
- 프롬프트/이미지에는 **가상 데이터만** 사용 (Jane Park, P-2041 Utility Work Lamp 등).
