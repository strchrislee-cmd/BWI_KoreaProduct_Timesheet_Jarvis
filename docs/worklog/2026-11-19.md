## A1. 시작 시간 범위 07:00–10:00
**요청** 시작 시간은 30분 단위로 07:00부터 최대 10:00까지.

**작업 내용**
- `src/domain/time.ts`에 `START_EARLIEST`/`START_LATEST`와 `startTimeOptions()`를 추가했습니다.
- Daily Log와 Settings의 시작 시간 선택(`TimeRangePicker`)이 이 범위를 씁니다.
- 예전에 저장된 값이 범위 밖이면(예: 06:30) 그 값도 목록에 남겨, 사용자가 다시 고를 때까지 그대로 표시합니다.

**작업 결과**
- 시작 옵션은 07:00, 07:30 … 10:00의 7개입니다. 종료는 이전처럼 시작 + 8h + 점심으로 맞춰지고 늘릴 수 있습니다.
- 단위 테스트와 브라우저 테스트로 확인했습니다.

## A2. 노션식 옵션 메뉴 + 랜덤 색
**요청** 첨부한 노션 메뉴처럼 자연스럽게(이름, 삭제, 색 목록). 색에 **랜덤**과 **랜덤(파스텔)** 추가.

**작업 내용**
- 새 컴포넌트 `src/components/ColorMenu.tsx`가 예전 `ColorPicker`를 대체합니다.
- 메뉴 구성(위에서부터):
  - 이름 입력칸
  - 삭제
  - 색 목록: 랜덤, 랜덤 (파스텔), 기본, 노션 9색(회색·갈색·주황색·노란색·초록색·파란색·보라색·분홍색·빨간색)
  - 내 색상
  - 직접 지정 (RGB)…
- 현재 색에는 ✓를 표시합니다.
- 메뉴는 화면 끝에 닿으면 반대쪽으로 열리고, 표나 카드에 가려지지 않습니다.
- 어디서 여는지에 따라:
  - 반복 업무: 드롭다운 옵션이나 오른쪽 칩의 `…`. 이름 변경·삭제·색을 모두 쓸 수 있습니다.
  - 카테고리: 이름이 그룹 마스터에서 관리되므로 색만 바꿉니다. 메뉴에 안내 문구가 나옵니다.
- 랜덤은 채도 70%·명도 48%, 파스텔은 60%·74%의 무작위 색상입니다.

**작업 결과**
- 이름 변경, 삭제, 랜덤·파스텔·노션 색, 직접 지정 색 보관이 모두 동작하고 새로고침 후에도 유지됩니다.
- 스크린샷: `batch_02_option_menu.png`(레포에는 커밋하지 않음)

## A4. 30분 브라우저 알림
**요청** 30분마다 브라우저 알림으로 기록을 재촉.

**작업 내용**
- `src/domain/reminders.ts`: 다음 :00/:30까지 남은 시간을 계산하고, 그 시점에 알릴 내용을 정합니다.
- 다음 경우에는 알리지 않습니다: 주말, 근무시간 밖, 점심시간, **이미 기록한 칸**.
- `src/components/ReminderScheduler.tsx`: 앱 안에서 타이머를 돌려, 예를 들어 10:00이 되면 방금 끝난 칸에 대해 `JARVIS · 30분 기록 — 09:30–10:00 업무를 기록해 주세요` 알림을 띄웁니다. 알림을 누르면 그날 Daily Log가 열립니다.
- Settings → **알림** 카드:
  - 켜기·끄기
  - 권한 요청
  - 권한 상태 표시(허용됨/차단됨/아직 묻지 않음/지원 안 함)
  - 테스트 알림

**작업 결과**
- 브라우저 테스트에서 가짜 시계로 월요일 09:50부터 12:31까지 시간을 흘려 확인했습니다.
  - 10:00에 비어 있던 09:30–10:00 칸 알림이 뜹니다.
  - 미리 기록해 둔 10:00–10:30 칸은 알리지 않습니다.
  - 11:00에 10:30–11:00 칸 알림이 뜹니다.
  - 점심 칸(12:00–)은 알리지 않습니다.

## A5. 옵션 드래그 이동
**요청** 셀렉트 아이템을 노션처럼 끌어서 순서 변경.

**작업 내용**
- `src/lib/useDragReorder.ts`: 포인터 기반 정렬 훅입니다. 마우스·펜·터치에서 모두 동작합니다.
- 드롭다운: 각 옵션 왼쪽의 손잡이(⋮⋮)로 끌어 놓습니다. 같은 그룹(그룹 프로젝트, Timelog, 로컬 섹션, 비업무, 반복 업무) 안에서만 움직입니다.
- 오른쪽 반복 업무 칩도 끌어서 순서를 바꿀 수 있습니다. 5px 넘게 움직였을 때만 드래그로 보고, 짧게 누르면 지금처럼 선택한 행에 적용합니다.
- 순서는 이렇게 저장합니다:
  - 반복 업무: `sort_order` 칼럼
  - 카테고리: 개인 설정 `categoryOrder`
- 끌어서 순서를 바꾸면 정렬 방식이 자동으로 "수동"이 됩니다.

**작업 결과** 드롭다운과 칩 양쪽에서 순서가 바뀌고, 새로고침 후에도 유지됩니다.

## A6. `…` 정렬 메뉴

- 생성일을 쓰려고 그룹 프로젝트와 반복 업무에 `created_at`을 읽어 옵니다(DB에는 이미 있던 칼럼).

**작업 결과** 정렬 메뉴의 현재 선택에 ✓가 표시되고, 오른쪽 칩 목록에도 같은 순서가 적용됩니다.

## A8. 글래스모피즘 + 배경
**요청** UI가 밋밋함. Bento grid는 유지하되 글래스모피즘으로. 배경 이미지 변경, 매일 Unsplash 무작위.
**추가 요청** Unsplash가 무료가 아니면 기본값은 무작위 그라데이션 패턴, 그리고 사진 업로드로 배경 지정.

**작업 내용**
- 스타일:
  - 반투명 유리 효과 클래스 `.glass`, `.glass-strong`, `.glass-sage`, `.glass-accent`, `.glass-dark`(`src/styles.css`)
  - 카드, 왼쪽 메뉴, 탭, 모달, 드롭다운, 로그인 화면에 적용
- 배경(`src/components/BackgroundLayer.tsx`). Settings → **배경** 카드에서 셋 중 하나를 고릅니다:
  1. **무작위 그라데이션 패턴**(기본)
     - 무작위 색 블롭 4개 위에 점·격자·줄무늬 중 하나의 패턴을 겹칩니다.
     - "매일 자동으로"를 고르면 날짜가 바뀔 때마다 새 패턴, "다른 패턴"을 누르면 그 패턴으로 고정됩니다.
  2. **내 사진**
     - 업로드한 사진을 긴 변 1920px JPEG로 줄여 저장합니다.
     - 저장 위치: Supabase는 새 테이블 `user_backgrounds`(본인만 접근 가능), 데모 모드는 브라우저
  3. **Unsplash 오늘의 사진**
     - Vercel 함수 `/api/background`가 Unsplash에서 사진 1장을 가져옵니다.
     - 결과를 한국 시간 자정까지 캐시해, 모든 사용자가 하루 동안 같은 사진을 보고 API 호출은 하루 1회 수준입니다.
     - Unsplash 이용 규칙에 따라 사진 아래에 작가와 출처를 표기하고, 사진을 쓸 때 다운로드 집계 요청을 보냅니다.
     - API 키가 없으면 이 선택지는 비활성화되고 그라데이션이 쓰입니다.
- DB: `supabase/migrations/0005_user_backgrounds.sql`
  - 본인만 읽고 쓰는 RLS. 관리자도 남의 배경은 볼 수 없습니다.
  - `data:image/` 형식만 허용하고, 크기는 약 3MB까지입니다.

**작업 결과**
- 그라데이션 패턴, 사진 업로드·삭제, 새로고침 후 유지, 로그인 화면 배경이 모두 동작합니다.
- 스크린샷: `batch_03_daily.png`, `batch_04_settings_upload.png`

## 발견하고 고친 문제
1. **빌드하면 유리 효과가 사라짐**
   - 원인: CSS에 `-webkit-backdrop-filter`와 `backdrop-filter`를 둘 다 적었더니, 빌드 도구(Lightning CSS)가 둘을 합치면서 Chrome이 무시하는 `-webkit-`만 남겼습니다.
   - 해결: 표준 속성만 적으면 빌드 도구가 두 가지를 알아서 출력합니다. 실제 화면에서 `blur(18px)`이 적용된 것을 확인했습니다.
2. **유리 효과 클래스가 hover 같은 Tailwind 유틸리티를 덮어씀**
   - 해결: `@layer components`로 옮겨 유틸리티가 우선하게 했습니다.

## 알려진 제약
- **알림은 JARVIS 탭이 열려 있을 때만 옵니다.** 브라우저를 완전히 닫아도 오게 하려면 Web Push(서비스 워커 + 푸시 서버)가 필요합니다. 필요하면 다음 단계로 진행하겠습니다.
- **Unsplash**
  - [unsplash.com/developers](https://unsplash.com/developers)에서 앱을 만들고 Access Key를 Vercel 환경변수 `UNSPLASH_ACCESS_KEY`에 넣어야 켜집니다.
  - 무료 데모 등급은 시간당 50회지만 하루 1회 캐시하므로 충분합니다. 무료 등급도 이용 규칙상 작가 표기가 필요하고, 화면에 이미 표시됩니다.
  - 이 개발 환경에서는 Unsplash 서버에 접속할 수 없어, 목업으로만 검증했습니다.
- **실제 Supabase 프로젝트에서는 아직 검증하지 않았습니다.** 로컬 Postgres로 마이그레이션과 권한을 검증했습니다. 이미 운영 DB가 있다면 `0005_user_backgrounds.sql`만 추가로 실행하면 됩니다.
