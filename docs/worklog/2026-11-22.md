## 1. Vercel 에이전트 설정 (https://vercel.com/get-started.md 안내서)
**요청** Vercel 안내서를 받아서 그대로 설정해 달라.

**작업 내용과 결과**
| 단계 | 결과 |
|---|---|
| 네트워크 | 이 클라우드 환경에 `vercel.com`, `api.vercel.com`을 허용했습니다(사용자 승인). 배포 확인용으로 `jarvis-timesheet-bay.vercel.app`도 추가했습니다 |
| 1. CLI | Vercel CLI 66.6.0 설치, 로그인 완료. 첫 두 번의 로그인 코드는 승인 전에 만료됐습니다(코드 유효시간 10분) |
| 2. 플러그인 | 설치하지 못했습니다(아래 참고) |
| 3. MCP | 연결하지 않았습니다. 클라우드 세션에서는 claude.ai 커넥터(https://claude.ai/customize/connectors)로 연결해야 합니다 |

**Vercel 플러그인을 설치하지 못한 이유**
- 이 세션의 자동 권한 검사가 설치를 거부했습니다. 플러그인이 에이전트 동작에 훅을 추가하기 때문입니다.
- 공식 문서를 확인해 보니, 설치를 하더라도 클라우드 세션은 플러그인을 불러오지 않습니다.
  - `/plugin` 명령이 동작하지 않습니다.
  - 레포 `.claude/settings.json`의 플러그인 설정도 불러오지 않습니다.
- 그래서 플러그인은 사용자 PC의 Claude Code(데스크톱 앱 로컬 세션 또는 CLI)에 설치해야 의미가 있습니다.
- 앞서 "저장소 범위로 설치하면 클라우드 세션에 적용된다"고 안내한 것은 틀렸습니다. 이 기록에서 정정합니다.

## 2. 첫 배포 (데모 모드)
**요청** 휴대폰에서 열어 볼 수 있게 해 달라. 공개 주소로 배포(사용자가 선택).

**작업 내용**
- Vercel 프로젝트 `jarvis-timesheet`를 만들었습니다. 개인 Hobby 계정이고, 프레임워크는 Vite로 자동 인식됐습니다.
- 운영 배포(`vercel deploy --prod`)를 했습니다. 환경변수 없이 데모 모드로 동작합니다.
- **배포 보호 설정을 바꿨습니다.**
  - 새 프로젝트의 기본값은 직접 연결한 도메인 외에는 모두 Vercel 로그인을 요구합니다(`all_except_custom_domains`).
  - 공개 주소가 로그인 없이 열리도록 `prod_deployment_urls_and_all_previews`로 바꿨습니다.
  - 지금은 공개 주소만 열리고, 배포마다 생기는 개별 주소와 미리보기 배포는 계속 Vercel 로그인이 필요합니다.
- 연결 과정에서 CLI가 바꾼 것을 정리했습니다.
  - `.gitignore`에 `.env*`를 추가했는데, 레포의 `.env.example`까지 무시 대상이 될 수 있어 되돌렸습니다.
  - CLI가 만든 `.env.local`(로컬 개발용 임시 토큰)은 업로드되지 않도록 지웠습니다.

**작업 결과**
- 로그인 없이 요청해서 모두 200으로 열리는 것을 확인했습니다:
  - `/`, `/timesheets`, `/settings`
  - `/api/background`(`{"configured":false}`, Unsplash 키가 없어 정상)
- 휴대폰 크기 브라우저(iPhone 15 에뮬레이션)에서 Daily Log 표와 데모 모드 안내가 뜨고, 콘솔 오류가 없었습니다.

## 알려진 제약
- **GitHub 자동 배포가 연결되지 않았습니다.** Vercel 계정에 GitHub 로그인 연결이 없어서입니다.
  - 지금은 push해도 사이트가 자동으로 갱신되지 않습니다.
  - Vercel 계정 설정에서 GitHub를 연결한 뒤 `vercel git connect`를 실행하면 push할 때마다 자동 배포됩니다.
