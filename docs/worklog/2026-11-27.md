# 2026-11-27 작업 기록

## 1. 단계별 열람 권한 + 조직도
**요청**
- L1은 개인 자료만, L2는 자기에게 속한 L1, L3는 자기에게 속한 L2와 L1을 계층으로 단계별로 볼 수 있게.
- 이를 위해 조직도 탭. L1·L2·L3 모두 조직도에서 전체 조직이 보이게. 조직 정보는 admin만 부여.
- L1이 L2의 자료를 보려면 요청 후 일시적으로 볼 수 있게.
- 상위 관리자가 하위 정보를 보는 창은 Today 같은 창에서 담당자 이름을 체크하면, 작성창과 같은 창이 본인 타임시트 아래로 죽죽 스크롤해서 보이게. 위치를 바꾸면 순서가 바뀌고, 모두 해제 후 다시 체크하면 체크한 순서대로.
- 결정(질문으로 확인): 승인은 **요청받은 그 L2 본인**, 기간은 **승인할 때 고름**(1시간·하루·1주), 범위는 **읽기만: Daily Log·Weekly Result·Kanban**, 조직 정보는 **보고 라인 + 팀 이름**.

**작업 내용**
- DB 마이그레이션 `0013_org_access.sql`
  - `profiles`에 `manager_id`(상위자)·`team`(팀 이름). 관리자만 바꿀 수 있고(기존 등급·내보내기 권한 보호에 추가), 보고 라인이 자기에게 돌아오면 거부.
  - `visible_user_ids()`: 나 / 관리자는 전원 / 보고 라인 아래에 있으면서 나보다 낮은 등급(L2 → 아래 L1, L3 → 아래 L2·L1) / 승인된 열람 요청(기간 안).
  - `time_slots`·`work_days`·`kanban_cards`·`kanban_moves`의 **읽기** 규칙만 이것으로 바꿈. 쓰기는 그대로 본인(관리자)만.
  - `access_requests`: L1이 L2에게만 요청(같은 L2에 열린 요청 하나), 답은 `decide_access_request()`로 요청받은 L2 본인만(승인 1·24·168시간 또는 거절). 요청한 사람·받은 사람·관리자만 봄. 로그인 안 한 접근은 모두 거부.
- **조직도 탭**(Timesheets 마지막): 보고 라인대로 들여쓴 전체 조직, 등급·팀 표시. 관리자는 줄마다 팀 입력과 상위자 선택(더 높은 등급이면서 아래 사람이 아닌 사람만, 높은 등급부터). 볼 수 있는 사람 옆 **보기**. L1은 L2 옆 **열람 요청**(요청 중 / ~까지 열람 / 거절됨·기간 끝 → 다시 요청). 오른쪽 **받은 열람 요청**에서 1시간·하루·1주 승인 또는 거절. 0013 실행 전에는 실행 안내만 보이고 모두 자기 기록만 봄.
- **팀원 창**: 볼 수 있는 사람이 있으면 Daily Log에 Today 같은 창(배치 편집·크기·오른쪽 Dock 동일, 예전에 저장한 배치는 팀원 창을 빠른 등록 아래에 둠). 체크한 사람은 위에 번호와 함께 체크한 순서로 모이고 끌어서 순서 변경, 모두 해제. 체크한 사람의 30분 기록이 내 기록 아래에 같은 표로 차례로(읽기 전용, × 숨기기, 크게 보기). 순서는 계정에 저장(`teamView`).
- 사람 고르기: L1~L3도 볼 수 있는 사람이 있으면 Timesheets 오른쪽 위에서 고를 수 있음(일일 기록·데일리 칸반·주간 결과 탭만, 읽기만). 휴가·그룹 타임시트·프로젝트·조직도 탭은 본인 것. 관리자는 예전처럼 전원.
- 데모 모드: 데이터베이스와 같은 규칙(볼 수 없는 사람의 기록은 비어 보임). 조직도의 **데모 팀원 만들기**로 가상의 팀원 5명(가상 이름)과 그날 기록·칸반, 데모 사용자에게 온 요청 하나를 만듦.
- 등급 설명(관리·설정의 등급 목록)을 새 규칙으로 바꿈. 탭이 하나 늘어 제목줄이 한 줄에 들어가도록 탭 좌우 여백을 조금 줄임.

## 적용 순서(중요)
- Supabase SQL Editor에서 `supabase/migrations/0013_org_access.sql`을 실행한 뒤 배포합니다. 실행 전에 배포해도 기록 저장·조회는 그대로 되고, 조직도에는 실행 안내가 보입니다.

## 검증
- 단위 테스트 156개(조직도 계산 6개, 배치·설정 읽기 추가), DB 테스트(관리자만 상위자·팀, 보고 라인 순환 거부, L2·L3 읽기 범위, 쓰기 불가, 요청·승인·기간 만료·거절, 같은 등급은 안 보임, 익명 차단) 통과.

## 배포

- 배포 후 할 일: 관리자가 조직도 탭에서 사람마다 상위자와 팀을 지정해야 L2·L3에게 아래 사람이 보입니다.

## 질문: SQL 파일을 하나로 합칠까

# (2차) 테스트 계정 5개 + Daily Kanban 팀원 보기

## 1. 테스트 계정
**요청**: 테스트해 볼 수 있게 가짜 데이터와 계정 5개를 만들고, 팀을 나눠 보이는지 안 보이는지 보고 싶다.
- 레포에 넣지 않는 SQL 한 파일(작업 공간)로 만들어 사용자가 SQL Editor에서 실행: 가상의 5명(한서윤 L3 개발본부 → 오하린 L2 설계팀 → 윤도현 L1, 정우진 L2 시험팀 → 서지아 L1), 받을 수 없는 `@teamembedded.test` 이메일, 공통 임시 비밀번호(채팅으로만 전달), 최근 평일 5일 기록, 칸반 카드, 윤도현 → 정우진 열람 요청 1건. 지우는 SQL도 함께.
- 실행 전 로컬 Postgres(Supabase와 같은 auth 표)에서 미리 돌려 확인, 실행 후 실제 DB에서 다섯 계정으로 로그인해 확인:
  - L3 한서윤: 넷 모두 / L2 오하린: 윤도현만 / L2 정우진: 서지아만(+ 받은 요청) / L1 둘: 본인만. 테스트 계정에서는 실제 사용자 기록이 보이지 않음.

## 2. Daily Kanban 팀원 보기 + 사람별 색
**요청**: Daily Log는 지금처럼 아래쪽으로. Daily Kanban에도 Team 체크를 넣고, 체크하면 그 사람 업무를 같은 Kanban에(카드에 이름). Team에 색을 줘서 인원별 색으로 필터링(노션 데이터베이스 참고).

**작업 내용**
- 보드 위 **팀원** 줄: 나(항상) + 볼 수 있는 사람 체크. 체크한 사람의 카드가 내 카드와 같은 칸에 들어옴(칸 안에서 나 → 체크한 순서, 사람마다 원래 순서). 카드에 이름표와 왼쪽 색 줄. 팀원 카드는 읽기만(끌기·… 메뉴 없음), 내 카드는 팀원 카드 사이로 끌어도 내 카드 순서만 바뀜. 체크는 계정에 저장(`kanbanTeam`, Daily Log 팀원 창과 따로).
- **사람별 색**: 이름 앞 색 점을 눌러 색 지정(프로젝트 색처럼 나에게만 적용, `person:<id>`). 정하지 않으면 조직도 순서대로 서로 다른 기본 색(회색 제외). Daily Log 팀원 창과 팀원 기록 제목에도 같은 색 점.
- **색으로 보기**(노션의 필터처럼): 쓰이는 색마다 칩(그 색 사람 이름), 누르면 그 색 사람의 카드만, 여러 개 고르기 가능, 같은 색 사람은 함께, 전체로 되돌림.
- 볼 사람이 없으면(L1) 팀원 줄이 나오지 않아 예전과 같음.

## 검증
- 단위 테스트 158개(여러 사람 보드 정렬·필터, 사람 색 기본값·저장값, 설정 읽기), DB 테스트 통과.
- 브라우저 테스트: Daily Kanban 팀원·색 필터(7단계, `batchT`) 추가, 색 점이 생긴 팀원 창에 맞춰 `batchS` 이름 찾기 수정. 전체 25묶음 통과.

## 배포 (2차)
- DB 변경 없음(설정은 profiles.preferences). https://teamembedded.vercel.app 배포, 실제 사이트에 새 코드가 들어간 것 확인.

# (3차) 팀원 기록 때문에 페이지가 내려가는 문제, 사람 고르기는 관리자만

## 요청
1. Team에 사람이 체크되어 있으면 Daily Kanban에 갔다가 Daily Log로 돌아올 때 세로 스크롤이 아래로 살짝 내려간다. Project 칸이 포커스돼서 그런가? 고쳐 달라.
2. 오른쪽 위 사람 고르기 상자는 admin만 되는 것인가? admin 외에는 없애 달라. 다른 사람은 Team 보는 곳에서 본다.

## 원인과 수정
1. 포커스가 아니라, 30분 표가 처음 나타날 때 "선택된 칸(07:30 Project)을 화면 안으로 스크롤"하는 동작 때문이었습니다. 내 기록 아래에 있는 팀원 기록 표도 처음 나타나며 자기 07:30 칸을 보이게 하려고 페이지를 내렸습니다(테스트에서 932px). 이제 표가 처음 나타날 때는 스크롤하지 않고, 사용자가 칸을 옮길 때만 그 칸을 화면 안으로 가져옵니다(키보드 이동 등 기존 동작 그대로).
2. 2차까지는 볼 수 있는 사람이 있는 L1~L3에게도 사람 고르기를 보여 줬습니다(일일 기록·칸반·주간 결과 탭). 이제 예전처럼 **관리자만**. 그와 함께 조직도의 **보기** 링크와 팀원 기록의 **크게 보기**도 관리자만(L1~L3에게는 "볼 수 있음" 표시만). L1~L3는 Daily Log 팀원 창과 데일리 칸반 팀원 줄에서 봅니다. DB의 읽기 규칙은 그대로입니다.

## 검증
- 브라우저 테스트 `batchS`에 "칸반 → Daily Log로 돌아와도 맨 위(스크롤 0)" 단계 추가: 고치기 전 932px로 실패, 고친 뒤 통과. 승인받은 L1 단계는 팀원 창·칸반 팀원 줄로 보고, 어느 탭에도 사람 고르기가 없는지 확인하도록 바꿈. 전체 25묶음, 단위 158개 통과.

## 배포 (3차)
- DB 변경 없음. https://teamembedded.vercel.app 배포, 실제 사이트에 새 코드가 들어간 것 확인.

# (4차) AI 정리 + 수정 제안(diff)

## 요청
- 관리자 계정에 AI API 키를 넣고, 직원들은 회사가 내는 비용으로 쓰게. 개인 설정에서는 AI 칸을 없애고, 직원 기록의 Task·Project·Type을 보정해 주는 역할.
- 결정: 가장 싼 모델, 1인당 하루 사용 횟수 제한, 누가 얼마나 썼는지 기록. 키는 관리자 화면에서만. AI 정리는 제안 → 확인 후 적용. 범위는 각자 자기 기록만.
- 새 기능: 관리자 쪽에서 diff처럼 수정 제안, 담당자도 AI 결과를 diff로 비교. (확인) 제안하는 사람은 admin + 상위자, 전달은 앱 안에서, 고칠 칸은 Task·Project·Type.

## 작업 내용
- DB 마이그레이션 `0014_ai_assist.sql`
  - API 키: API로 드러나지 않는 `private` 스키마에 저장. 관리자만 `set_ai_key`(넣기·지우기), `ai_key_hint`는 끝 4자리만, `get_ai_key`는 서버(service role)만.
  - `org_settings.ai_daily_limit`(기본 10), 모델은 Claude Haiku 5.5로.
  - `ai_usage`: 누가·언제·누구 기록을·토큰·비용(US$). 본인 것만 보이고 관리자는 전부. 쓰기는 서버만. `ai_begin`이 한국 시간 하루 횟수를 사람별로 잠그고 세어 넘으면 거부.
  - `correction_proposals`: 받는 사람·보낸 사람·날짜·바꿀 줄(전/후/이유)·메모·AI 여부·상태. 관리자는 누구에게나, 그 밖에는 조직도에서 아래에 있는 낮은 등급에게만(`can_propose`). 받는 사람은 `answer_proposal`로 적용한 줄을 한 번 답하고, 보낸 사람은 답하기 전이면 취소.
- 서버 함수 `/api/ai/cleanup`(Vercel): 로그인 확인 → AI 켜짐 → (다른 사람이면) 제안 권한 → 키 → 그날 기록을 직접 읽어 같은 업무끼리 묶음 → 하루 횟수 → Claude Haiku 5.5에 구조화된 JSON으로 요청(노력 low) → 모르는 번호·바뀐 게 없는 제안은 버리고 돌려줌. 실패한 호출은 횟수에서 빼고, 응답 거절은 비용만 기록. 프로젝트·유형은 짧은 번호(p1, t1)로 보내 토큰을 줄임. 테스트할 수 있게 핵심 로직(`api/_lib/aiCleanupCore.ts`)과 연결 부분을 나눔.
- 화면
  - 개인 설정의 AI 칸 삭제, 관리자 화면에 **AI 정리** 카드(켜기·하루 횟수·API 키·사람별 30일 사용량).
  - Daily Log **AI 정리**: 비교 화면(지운 글자 → 새 글자, 이유), 줄마다 체크, 고른 줄만 적용(Ctrl+Z 가능, 그사이 바뀐 칸은 건너뜀), 남은 횟수 표시.
  - 팀원 기록 **수정 제안**: 줄마다 고치기 + AI로 채우기 + 메모, 받는 사람에게 보일 비교 화면 미리보기, 보내기.
  - Daily Log 위 **받은 수정 제안** 알림 → 같은 비교 화면에서 고른 줄 적용 / 모두 적용 안 함.
  - 조직도 **보낸 수정 제안**: 상태, 비교 보기, 취소.

# (5차) Daily Kanban: 그날의 카드, 하루 되감기, Kanban Flow

## 요청
- 칸반에 하루를 30분 간격으로 어떤 일을 Doing으로 했는지, 스크롤을 옮기며 블록이 이동하는 것을 보는 UI.
- 칸반 아래 **Kanban Flow**: 30분 간격으로 선택된 사용자마다 어떻게 이동했는지 하루 전체 그래프.
- 결정(질문으로 확인): 되감기는 **Daily Log 기준**(손으로 옮긴 건 옮긴 시각에), 그래프는 **카드별 상태 흐름**.
- (버그) Daily Kanban은 그날의 내용을 보여 줘야 하는데, 오늘 기록은 Andon뿐인데 지난 데이터가 넘어온다.

## 원인과 수정
- 처음 만들 때 "보드 하나로 날짜와 상관없이 계속"으로 정해서, 지난 업무 카드가 Wait에 계속 남아 보였습니다. 이제 위에서 고른 **날짜의 카드만**(그날 Daily Log에 기록됐거나 그날 손으로 옮긴 카드) + Backlog·ToDo(아직 할 일)를 보여 줍니다. 카드 자체와 이동 기록은 그대로 두고, **지난 카드도 보기**로 전부 볼 수 있습니다.

## 작업 내용
- `replayDay`(순수 함수): 한 사람의 보드를 그날 30분씩 다시 계산. 그 칸에 기록한 업무가 Doing, 그 전 Doing은 Wait(점심·빈 칸은 그대로), 손으로 옮긴 이동(DoneCheck·Done 등)은 옮긴 30분에 반영. 하루의 시작 상태는 그날 첫 이동 전의 칸. 그날 기록했지만 나중에 지운 카드도 그날에는 보임. 그날 움직인 카드 목록도 함께 돌려줘서 "그날의 카드" 판단에 씀.
- 칸반 위 **하루 되감기** 슬라이더(근무 시작 ~ 마지막 기록, 끝은 오늘이면 "지금", 지난 날짜는 "하루 끝"). 되감기 중에는 읽기 전용, 그 30분에 옮겨진 카드는 노란 테두리, "지금으로" 버튼.
- 보드 아래 **Kanban Flow**: 사람(나 + 체크한 팀원)마다 그날 움직인 카드가 한 줄, 30분마다 칸 색(Doing은 그 사람 색, Wait 연한 색, DoneCheck·Done 회색, Backlog·ToDo 테두리). 칸을 누르면 그 시간으로 되감기, 되감은 시각은 굵은 테두리.
- 카드 이동 기록 읽기(`listKanbanMoves`)를 저장소에 추가(볼 수 있는 사람만, 0013 규칙 그대로). 데모 팀원 카드도 실제처럼 "만들어짐" 이동을 기록.

## 검증
- 단위 테스트 169개(되감기: Doing/Wait 순서, 점심, 손 이동 시각, 지운 카드, 그날의 카드 판단), 브라우저 테스트: 그날의 카드·되감기·Kanban Flow(6단계, `batchV`) 추가, 전체 27묶음 통과. DB 변경 없음.

# (7차) Daily Kanban 다시 만들기: Log Enable, 같은 업무 한 블록 + 사람 아이콘, Doing만 보는 Flow

## 요청
- 원래 계획: Kanban 모드에서 **Log Enable**을 켜면 정각·30분마다 "Doing에 있는 내용을 Log로 기록하겠습니까?" 팝업을 띄워 한 번에 기록, 다르면 **수정**으로 다른 업무를 Doing에 놓고 Daily Log에는 바뀐 업무로 기록.
- Flow에는 다른 정보 없이 **Doing에 무엇을 했는지**만. 칸반 카드가 Doing으로 옮겨가고 그 블록에 **Figma 공동 작업처럼 사용자 아이콘**이 붙어, 원하는 사람을 체크해 두면 시간에 따라 어떤 Doing이 이루어지는지 보기.
- 지금 버전은 언제든 돌아올 수 있게 백업 이름을 남기기.
- 결정(질문으로 확인): 팝업은 **앱 어디서나**, 팀원 카드는 **같은 업무는 한 블록**, Flow는 **사람별 한 줄**.

## 백업
- 바꾸기 전 버전을 **`backup-kanban-v1`**(커밋 `5c73eb2`, 그때 배포본 `teamembedded-n1qnex2qm-chris-hobby.vercel.app`)으로 남겼습니다. 되돌리는 방법은 [`docs/backups.md`](../backups.md). "backup-kanban-v1로 돌려 주세요"라고 하면 됩니다.

## 한 것
- **Log Enable**(보드 위 고정 막대): 켜면 정각·30분마다 앱 어느 화면에서나 오른쪽 아래 팝업 "{시간} 을 Doing 업무로 기록할까요?"(브라우저 알림도).
  - **기록**: 그 30분을 Doing 카드의 Project·Type·Task로 Daily Log에 저장.
  - **수정**: 카드 목록(Wait → ToDo → Backlog 순)에서 고르면 그 카드가 Doing으로, 원래 Doing은 Wait로 옮겨지고(손 이동으로 기록) 그 업무로 저장. Doing이 비어 있으면 바로 목록.
  - **건너뛰기**: 저장 안 함. 이미 기록된 30분·점심·근무시간 밖·주말은 묻지 않음. 켜 있는 동안은 30분 알림 입력 창 대신 이 팝업. 열린 보드와 Daily Log는 바로 다시 읽음.
- **팀원 카드는 Doing에만**, 같은 업무(Project·Type·Task)는 **블록 하나**에 사람 아이콘(이름 첫 글자, 사람 색)이 여러 개. 내 카드와 같으면 내 카드에 붙음(내 카드는 그대로 끌기·메뉴 가능). 카드 왼쪽 색 줄·이름표는 아이콘으로 바꿈.
- **Kanban Flow를 Doing만**: 사람마다 한 줄, 시간에 따라 Doing이던 업무를 이름 붙은 블록으로(같은 업무는 모두에게 같은 색). 블록의 누른 위치의 30분으로 되감기. 어제부터 Doing이던 카드는 그날 기록하거나 옮기기 전까지 Doing으로 치지 않음(되감기 보드에서도 Wait). 오늘은 지금 30분까지만 그림(아직 오지 않은 시간에 Doing이 이어져 보이지 않게).

## 검증
- 단위 테스트 170개(같은 업무 한 블록·색 필터, 어제 Doing 카드는 그날 Wait로 시작), DB 테스트 통과(DB 변경 없음).
- 브라우저 테스트: `batchW`(Log Enable: 09:30 이미 기록 → 없음, 10:00 기록, 10:30 수정 → 견적 검토 Doing·도면검토 Wait, 11:00 Daily Log 화면에서도 팝업·건너뛰기, 끄면 안 뜸) 추가, `batchT`(Doing 블록·아이콘·합치기), `batchV`(Doing만 Flow) 갱신. 고정 막대 단계는 보드가 짧아져 480px 높이 화면에서 확인.

## 배포 (7차)

# (9차) 버그: 아무것도 안 했는데 지난 카드가 Wait에 남음

## 요청
- 오늘 Daily Log에는 Andon Jidoka(Task 없음)만 있는데, Daily Kanban의 Wait에 다른 카드(예전 업무)가 노란 테두리로 남아 있다.

## 원인
- 보드는 "그날 Daily Log에 기록됐거나 그날 손으로 옮긴 카드"만 보여 줍니다. 노란 테두리는 그 30분에 옮겨졌다는 뜻이라, 그날 16:00대에 그 카드가 "손으로 옮김"으로 기록된 것.
- 손 이동을 기록하는 곳은 보드에서 끌기·메뉴와 **Log Enable 팝업의 수정**뿐. 수정으로 다른 카드를 고르면 원래 Doing 카드를 Wait로 보내는데, 이것도 "손으로 옮김"으로 기록하고 있었습니다. 그래서 그날 기록이 없는(지웠거나 지난 날의) 카드가 오늘의 카드로 잡혀 Wait에 남았습니다. 데모에서 같은 순서로 재현해 화면 그대로 나오는 것을 확인.

## 수정
- 팝업에서 **고른 카드만** 손 이동으로, 밀려나 Wait로 가는 카드는 기록(log)에 따른 이동으로 남김. 이미 남은 이동 기록 때문에 그 카드는 오늘 보드에는 계속 보이고, 내일부터는 안 보임.
- 브라우저 테스트 `batchW`에 "수정 때 Wait로 밀려난 카드는 그날 기록을 지우면 오늘 보드에 남지 않음" 단계 추가(고치기 전 코드에서는 실패하는 것 확인). Kanban 묶음 통과.

# (10차) Log Enable 수정은 직접 적기, Daily Kanban은 그날 카드만

## 요청
- 수정을 누르면 직접 타이핑해서 고치게(Task는 타이핑, Project·Type은 선택). 이전 칸반에 남아 있던 카드 목록을 보여 주는 건 의미 없음.
- 지난 카드도 보기는 그날 하루에 일어난 카드만.
- 30분씩 옮길 때 이전 30분과 지금 30분 사이에 바뀜이 있을 때만 카드 2장, 나머지는 그날 카드만. 전날·전전날 등 다른 날 카드는 보여 주지 말 것.
- 결정(질문으로 확인): 보드는 **Doing + 바뀐 2장**(지난 카드도 보기는 그날 앞선 카드까지, 지금 보드도 같은 규칙), Backlog·ToDo도 **그날 것만**.

## 한 것
- **수정 = 직접 적기**: Project·Type 선택, Task 타이핑(지금 Doing 카드 값이 미리 들어 있음). 기록하면 Daily Log와 같은 방식으로 저장하고 보드를 그 기록에 맞춤(그 업무가 Doing, 없던 업무면 새 카드, 원래 Doing은 Wait — 모두 기록에 따른 이동). Doing이 비어 있으면 바로 적는 칸. 예전 카드 고르기 목록은 없앰. 30분 알림의 입력 칸과 같은 Project·Type 목록을 공용으로 씀.
- **그날 카드만**: 카드마다 그날 처음 들어온 30분(그날 기록, 그날 만들기, 그날 손으로 옮기기)을 계산해, 그 전에는 보이지 않게. 다른 날 카드(어제 하던 Doing, 지난주 Wait, 예전 Backlog)는 어느 시간에도 안 보임.
  - 기본: 그 30분의 Doing 카드 + 그 30분에 바뀐 카드(Doing이 바뀌면 새 Doing과 Wait로 간 카드 2장, 손으로 Done 옮긴 카드 등). 지금 보드는 마지막으로 기록된 30분부터의 바뀜까지.
  - 지난 카드도 보기: 그날 그때까지 들어온 카드 전부(그 시점의 칸에).
  - 지금 보드에서 팀원 카드는 그 사람 Daily Log의 지금 시점대로, 내 카드는 저장된 칸 그대로(끌기·메뉴용).

## 검증
- 단위 테스트 170개(그날 카드 규칙: 바뀜 2장, 지난 카드도 보기, 손으로 만든 Backlog, 다른 날 카드 없음), 브라우저 테스트 `batchW`(수정 직접 적기: Project·Type·Task → 새 카드 Doing, 도면검토 Wait, 카드 목록 없음 / 기록을 지우면 밀려난 카드는 지난 카드도 보기에서도 없음), `batchV`(기본은 Doing만, 지난 카드도 보기는 오늘 앞선 카드까지, 14:30처럼 바뀜이 없으면 Doing만), `batchT`(시계 13:10, 팀원은 Daily Log의 지금 시점대로) 갱신.

# (11차) Log Enable 팝업도 브라우저 알림으로

## 요청
- 칸반에서 30분마다 뜨는 팝업도 Daily Log처럼 브라우저 알림으로 받아, 다른 일을 하다가도 누를 수 있게.

## 원인과 수정
- 알림 자체는 이미 보내고 있었지만, 브라우저 알림 권한은 Settings → 알림을 켤 때만 물어서, Log Enable만 켠 경우엔 권한이 없어 알림이 안 갔습니다.
- 이제 **Log Enable을 켤 때 브라우저 알림 권한을 묻습니다**(Settings와 같은 방식). 차단되어 있으면 "앱 안의 팝업만 뜬다, 주소창 사이트 설정에서 허용" 안내.
- 알림을 누르면 TeamEmbedded 탭이 앞으로 나오고 **Daily Kanban**으로 가며, 팝업은 그대로 떠 있어 바로 기록·수정·건너뛰기.
- 브라우저 테스트 `batchW`: 켤 때 권한을 한 번 묻고 허용됨, 10:00 알림 내용, Daily Log 화면에서 받은 11:00 알림을 누르면 /timesheets/kanban 으로 가고 팝업 그대로.
