# 2026-11-24 작업 기록

## 1. 비밀번호 로그인
**요청**
- 비밀번호가 없어 불편합니다. 한 PC에서 관리자 계정과 일반 계정을 시크릿 창으로 동시에 열어 보고 싶은데 안 됩니다.
- 로그인 메일이 오지 않습니다(스팸함에도 없음).

**원인**
- 로그인 방식이 메일 링크뿐이었습니다. 메일에서 링크를 누르면 기본 브라우저의 일반 창이 열려, 시크릿 창에서 요청해도 일반 창이 로그인됩니다.
- 크롬은 시크릿 창끼리 로그인을 공유합니다. 두 계정을 동시에 쓰려면 일반 창과 시크릿 창(또는 다른 브라우저)으로 나눠야 합니다.
- 메일이 안 오는 문제는 이 화면에서 확인할 수 없습니다(아래 "확인할 것"). 비밀번호 로그인으로 평소 로그인에는 메일이 필요 없게 했습니다.

**작업 내용**
- 로그인 화면: **이메일 + 비밀번호**가 기본입니다.
  - 틀리면 "Wrong e-mail or password…"와 함께 비밀번호가 없을 때의 방법을 안내합니다.
  - **Forgot password?**를 누르면 기존 메일 링크 로그인으로 바뀝니다(계정은 만들지 않음).
- 설정: **비밀번호** 카드(새 비밀번호, 한 번 더 입력, 8자 이상). Supabase 모드에서만 보입니다(데모는 로그인이 없음).
- 관리 화면 초대 칸: **임시 비밀번호(선택)**.
  - 넣으면 메일 없이 바로 계정을 만들고 이메일을 확인된 상태로 둡니다. 버튼이 Create account로 바뀝니다.
  - 이미 계정이 있는 주소면 비밀번호를 그 값으로 바꿉니다(초대 메일이 안 와서 막힌 동료도 바로 들어올 수 있음).
  - 비워 두면 전처럼 초대 메일을 보냅니다.
- 초대 API(`api/_lib/inviteCore.ts`): 임시 비밀번호 경로 추가, 8자 미만이면 아무것도 저장하지 않고 거부. 비밀번호 규칙은 `src/domain/password.ts` 한 곳에서 화면과 API가 같이 씁니다.
- README: 로그인 방식, 첫 관리자 만들기(Create new user + 비밀번호), 공개 가입 끄기 권장 이유.

**확인할 것(사용자)**
- 메일이 안 올 때:
  - 로그인 화면에 오류가 없었다면 Supabase는 메일을 Gmail SMTP에 넘긴 것입니다.
  - SMTP에 쓴 Gmail 계정과 받는 주소가 같으면 Gmail이 받은편지함이 아니라 **보낸편지함·전체보관함**에만 넣는 경우가 있습니다.
  - Supabase → Logs(Auth)에서 메일 발송 오류가 있는지 봅니다.
  - 회사 메일은 서버에서 격리되어 스팸함에도 안 보일 수 있습니다(IT 격리함).
- Supabase → Authentication → Sign In / Providers에서 **Allow new users to sign up**을 끄길 권합니다. 지금은 켜져 있습니다.

**검증**
- 단위 테스트 105개 통과(초대 임시 비밀번호 3개, 비밀번호 규칙 2개 추가).
- 브라우저 테스트(가짜 Supabase에 연결한 빌드, 15단계): 비밀번호 로그인 성공·실패 안내, Forgot password 링크 요청, 설정에서 비밀번호 저장(짧음·불일치 거부), 관리 화면 임시 비밀번호 계정 만들기(짧으면 거부, 관리자 토큰과 함께 전송), 데모 모드에는 비밀번호 카드 없음.
- 기존 브라우저 묶음(초대, e2e, batchB, mobile, batchE) 통과.
- 실제 Supabase: 비밀번호 로그인이 켜져 있습니다(없는 주소로 시도 → "Invalid login credentials").

## 커밋
- `Password sign-in, set a password in Settings, temporary passwords on invite`

## 2. 메일 링크를 눌러도 아무 일도 없던 문제
**증상**
- 회사 메일(Outlook)로 받은 "Reset your password" 링크를 눌렀더니 로그인 화면만 나오고, 비밀번호를 정하는 칸도 없고 로그인도 안 됐습니다.

**원인**
- 링크가 실패하면(이미 쓰였거나 만료) Supabase는 이유를 주소창(`#error_code=otp_expired…`)에 붙여 돌려보내는데, 앱이 이를 무시하고 빈 로그인 화면만 보여 줬습니다.
- 회사 메일 보안 기능(예: Outlook Safe Links)은 사람이 누르기 전에 링크를 먼저 열어 검사합니다. 메일 링크는 한 번만 쓸 수 있어서, 검사가 먼저 쓰면 사람이 누를 때는 이미 만료 상태입니다. 이번 경우의 가장 유력한 원인입니다.
- 링크가 성공하더라도 비밀번호를 정하라는 안내가 없었습니다.

**수정**
- `src/lib/authLink.ts`: 앱이 열릴 때 주소창의 링크 결과(성공/실패 이유)를 한 번 읽습니다.
- 실패한 링크: 로그인 화면에 이유를 보여 줍니다("This e-mail link was already used or has expired…", 비밀번호나 관리자 임시 비밀번호로 로그인하라는 안내). 주소창은 정리합니다.
- 성공한 링크(초대, Forgot password, 비밀번호 재설정): 로그인 후 **설정**으로 이동하고, 비밀번호 카드에 안내 문구를 띄우고 새 비밀번호 칸에 커서를 둡니다.

**검증**
- 단위 테스트 110개 통과(링크 결과 읽기 5개 추가).
- 브라우저 테스트(가짜 Supabase, 21단계): 만료 링크 → 이유 표시·주소창 정리, 재설정 링크 → 설정 이동·안내·커서, 다시 열면 안내 없음. 기존 묶음(e2e, 초대, batchB, mobile, grid) 통과.

## 커밋 (2차)
- `Explain failed e-mail links on the login screen; after a link sign-in, ask for a password`

## 3. 관리 화면 Users 표에서 비밀번호 설정·계정 삭제
**요청**
- Invitations의 삭제를 눌렀는데 Users에 계정이 남아 있습니다. Users에서 어떻게 지우나요?
- (선택) Users 표의 각 줄에 비밀번호 설정과 계정 삭제 버튼을 둘 다 넣기.

**작업 내용**
- Invitations의 **삭제**는 초대 기록만 지웁니다(로그인 계정은 남음). 이를 안내하고, Users 표에 버튼을 넣었습니다.
- Users 표 각 줄(본인 제외):
  - **비밀번호**: 창에서 임시 비밀번호(8자 이상)를 넣고 저장 → 메일 없이 그 비밀번호로 바뀝니다. Supabase 모드에서만 보입니다.
  - **삭제**: 확인 창("되돌릴 수 없습니다") 후 로그인 계정과 그 사람의 시간 기록·휴가·근무시간·업무 템플릿·개인 별칭을 지웁니다. 초대 기록도 함께 지웁니다.
  - 본인 줄에는 버튼 대신 "나 · 비밀번호는 설정에서"를 보여 줍니다.
- 새 API `POST /api/admin/user`(관리자만, `api/_lib/userAdminCore.ts`): `set_password` / `delete`. 본인과 마지막 관리자는 지울 수 없습니다(`deleteUserProblem`, 데모 저장소도 같은 규칙).

**검증**

## 5. 30분 알림에서 바로 입력하는 토스트
**요청**
- 30분 알림이 울리는 곳에서 바로 입력할 수 있게 토스트 팝업으로 입력창을 보여 주기.
- 토스트에 **이전 업무 연속 진행** 버튼: 누르면 이전에 기록한 내용이 그대로 기록되게.
- (선택) 입력칸은 Daily Log와 같은 3칸, 이전 업무 계속은 마지막 기록 이후 빈 칸 모두.

**확인한 제약**
- Windows·브라우저의 알림 창에는 글자 입력칸을 넣을 수 없습니다(브라우저가 허용하지 않음). 그래서 입력은 TeamEmbedded 화면 안의 토스트에서 하고, 바깥 알림은 지금처럼 울려 탭을 앞으로 가져옵니다.

**작업 내용**
- `src/components/ReminderToast.tsx`: 알림 시각마다 화면 오른쪽 아래(휴대폰은 하단 탭 위)에 토스트. 어느 페이지에서든 뜹니다.
  - 대분류(Category, 대분류별 묶음·No 표시, 비업무 포함), 업무분류(Sub Category), 업무내용(Content). 저장 방식은 Daily Log 한 줄과 같습니다(별칭·프로젝트 매핑 그대로).
  - **저장**: 하나라도 입력해야 켜집니다. **나중에**: 닫기만 합니다. 다음 알림이 오면 새 시간대로 바뀝니다.
  - **이전 업무 계속**: 오늘 마지막으로 기록한 칸의 3칸 내용을 그 뒤 빈 칸에 모두 넣습니다(점심·이미 적은 칸·근무 시작 전은 제외). 버튼 아래에 "무엇 → 몇 시–몇 시(n칸)"를 미리 보여 주고, 앞에 기록이 없으면 꺼집니다.
  - 저장 직전에 그날 기록을 다시 읽어, 그사이 Daily Log에서 적은 칸을 덮어쓰지 않습니다.
  - 저장하면 열려 있는 Daily Log가 바로 새로고침됩니다.
- `continuePlan`(`src/domain/reminders.ts`): 이전 업무 계속이 채울 칸 계산.
- 브라우저 알림 권한이 없어도 토스트는 뜹니다(알림 설정이 켜져 있으면).
- 설정 → 알림: 안내 문구와 **입력 창 띄워 보기** 버튼(방금 끝난 30분으로 바로 시험).

**검증**

## 6. 사이트 주소 변경: teamembedded.vercel.app
**요청** 주소도 timecrumbs.vercel.app에서 teamembedded로 바꾸기. 예전 주소는 새 주소로 자동 이동(선택).

**작업 내용(Vercel)**
- 새 주소 **https://teamembedded.vercel.app** 을 프로젝트에 추가했습니다(비어 있어서 바로 확보).
- 예전 주소 `timecrumbs.vercel.app`과 처음 주소 `jarvis-timesheet-bay.vercel.app`은 **새 주소로 자동 이동(308)** 합니다. 예전 링크·북마크도 그대로 열립니다.
- Vercel 프로젝트 이름을 `teamembedded`로 바꿨습니다.
- 초대 메일이 돌아올 주소 `APP_URL`(Production)을 새 주소로 바꾸고 다시 배포했습니다.
- README의 데모 주소, `.env.example`의 `APP_URL` 예시.

**사용자가 할 일(Supabase)**
- Authentication → URL Configuration: **Site URL**을 `https://teamembedded.vercel.app`으로, **Redirect URLs**에 `https://teamembedded.vercel.app/**`를 추가합니다.
- 바꾸기 전에도 메일 링크는 예전 주소로 갔다가 새 주소로 자동 이동하므로 동작합니다.
