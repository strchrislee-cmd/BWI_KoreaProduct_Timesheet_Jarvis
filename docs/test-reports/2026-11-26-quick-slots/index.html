요청

Quick add에 프리셋 슬롯 4개: 분기·시즌마다 저장해 두고 쓰다가 과거 업무가 돌아오면 그 슬롯으로 돌아가 쓰기. 드롭다운의 손잡이와 번호 사이 간격 줄이기.

인수 기준

  1. Quick add 창에 슬롯 탭 4개(기본 이름 1Q·2Q·3Q·4Q, 항목 수 표시), 하나만 사용 중.
  2. 사용 중인 슬롯의 항목만 표·Task 드롭다운·휴대폰 입력 창에 보이고, 새로 저장하면 그 슬롯에 들어간다.
  3. 슬롯을 바꾸면 그 슬롯의 항목으로 바뀌고, 다시 돌아오면 예전 항목 그대로.
  4. 같은 업무를 다른 슬롯에도 저장할 수 있다.
  5. 슬롯은 더블클릭해서 이름을 붙일 수 있고(예: 2026 Q1), 사용 중인 슬롯과 이름은 사람마다 저장된다.
  6. 드롭다운의 번호 칸은 가장 긴 번호만큼만 넓어서 손잡이와 번호 사이가 붙어 있다.

증적 (주석 스크린샷)

빨간 테두리와 번호는 표의 테스트 케이스 번호입니다. 그 요소를 확인해 판정했습니다.

용어
테스트 리포트 (Test Report)
무엇을 어떻게 확인했고 결과가 어땠는지 정리한 검증 보고서. 이 문서.
테스트 케이스 (Test Case)
확인 항목 하나. 표의 한 줄.
인수 기준 (Acceptance Criteria)
요청이 "다 됐다"고 볼 조건. 테스트 케이스는 여기서 나온다.
기대 결과 / 실제 결과 (Expected / Actual)
나와야 하는 것과 실제로 나온 것. 판정 근거의 조건을 만족하면 PASS.
단언 (Assertion)
판정 조건을 코드로 쓴 것. 표의 "판정 근거" 열.
증적 (Test Evidence)
통과를 보여 주는 증거. 여기서는 주석 스크린샷.
주석 스크린샷 (Annotated Screenshot)
확인한 요소에 빨간 테두리와 테스트 케이스 번호를 그린 화면.
E2E 테스트 (End-to-End)
실제 브라우저(Chromium)로 사용자처럼 눌러 보며 확인하는 테스트. 이 보고서의 테스트.
단위 테스트 (Unit Test)
함수 하나를 따로 확인하는 테스트(npm test).
회귀 테스트 (Regression Test)
새 기능 때문에 예전 기능이 깨지지 않았는지 전체를 다시 돌리는 것(npm run test:e2e).
추적성 (Traceability)
요청 ↔ 테스트 ↔ 커밋을 서로 찾아갈 수 있게 연결해 두는 것. 머리말의 커밋·스위트 정보.
